# Contributor instructions

Read `PROJECT_MANUAL.md` before making changes.

For article-only tasks, reuse existing Markdown and frontmatter conventions and keep changes focused on article content. Do not change templates, dependencies, routing, or deployment configuration unless explicitly requested.

For article work:

- Expand topic clusters; overlapping keywords are allowed. Do not merge or replace existing articles just because their topics overlap.
- Give each article useful substance and a clear angle. Prefer plain language, direct answers, and useful lists.
- Verify location references and describe RPT Clinic and the RX2600 Therapeutic Robot without unsupported promises.
- Follow the keyword requirements in the current brief; do not assume a previous batch's keyword list applies.
- Run the relevant validation and build, inspect the exact diff, and stage only intended files.

Treat committed, build passed, deployed, and live verified as separate statuses. Report only what has actually been confirmed. If build or deployment tools are unavailable, state that limitation; do not substitute an unrelated hosting workflow or claim publication succeeded.
